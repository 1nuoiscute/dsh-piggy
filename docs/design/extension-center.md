# 扩展中心设计（待确认）

> 2026-10-05 · 状态：设计稿，等用户确认后整体实现、整体发版（预计 v0.28.0，只更新游戏包，不动桌面程序）。

## 1. 要解决什么

玩家反馈：番茄钟、钓鱼这类玩法不是人人都要，希望能关掉，主菜单清爽一些；后面还会加种菜、盲盒、小游戏、天气……如果每个都硬塞进主菜单，会越来越乱。

所以：把这类玩法做成**扩展**。每个扩展可以单独开关；关掉后它在界面上完全消失、后台也不再结算，数据原样保留；再打开时一切恢复。

这一版的范围：

- 建立扩展的统一格式（注册表），把**番茄钟、钓鱼**改造成第一批扩展；
- 新增「扩展」App，在里面开关；
- 以后的种菜、盲盒、小游戏都按这个格式加进来。

不在这一版：在线下载扩展（第 9 节只写清边界）。

## 2. 什么算扩展

一个**可以整体关掉、关掉后不影响其他玩法**的玩法模块。判断标准：关掉它，猪照样能吃、玩、洗澡、打工、上学、旅行，存档不坏。

| | 第一批 | 以后 |
|---|---|---|
| 扩展 | 番茄钟、钓鱼 | 种菜、盲盒、小游戏合集、天气…… |
| 不是扩展（核心） | 照料、商店、背包、学习、打工、旅行、图鉴、换肤、设置、更新 | |

## 3. 扩展的格式（注册表）

新文件 `packages/pet-core/src/data/extensions.js`，每个扩展一条：

```js
{
  key: 'fishing',
  label: '钓鱼',
  emoji: '🎣',
  description: '抛竿、看准时机提竿，钓到的鱼进鱼篓，可以喂猪或卖钱',
  defaultOn: true,
  apps: ['fishing'],                 // 主菜单格子 / 图标栏
  actions: ['fishCast', 'fishHook', 'fishResolve', 'fishKeep', 'fishAuto', 'fishSkip'],  // 关掉后拒绝
  dexSections: ['fish'],             // 图鉴分区
  shopKinds: ['bait'],               // 商店货架
  busy: state => …,                  // 正在进行中的说明（见第 5 节），没有就返回 null
}
```

番茄钟同理：`apps: ['pomodoro']`、`actions: ['pomodoro', 'pomodoroAbandon']`、角标、状态页那一行。

核心统一提供 `extensionOn(state, key)`，各处只问这一个函数，不再各写各的判断。

## 4. 开关存在哪

**存在存档里**：`state.extensions = { pomodoro: true, fishing: true }`。

- 理由：关掉后核心要停掉番茄钟的到点结算、拒绝钓鱼动作，只有存档里的开关核心看得到。
- DSH 里的猪和桌面版的猪各有各的存档，所以两边可以分别开关。
- 老存档用 `ensureExtensions(state)` 补成全部打开，**不升存档版本**；认不出的 key 原样保留（以后降级再升级不丢开关）。

## 5. 正在进行中时能不能关

| 情况 | 建议做法 |
|---|---|
| 番茄钟专注中 | 开关置灰，写「这一个专注结束后才能关」 |
| 猪正在外面自动钓鱼 | 开关置灰，写「猪钓鱼回来后才能关」 |
| 钓鱼检定（QTE）中 | 不会遇到：开关在「扩展」App 里，进去时钓鱼页已经离开，检定按现有规则自动判失败 |

这样不会有「关掉时奖励给不给、鱼饵退不退」这类说不清的情况，数据也不会丢。另一种做法是「放弃这一个并关闭」（番茄钟不给奖励、自动钓鱼召回并退饵），需要你定。

## 6. 关掉之后什么消失、什么保留

**消失**

- 主菜单格子、图标栏；正开着这个 App 时退回主菜单；
- 番茄钟：猪身上的计时角标、专注结束的提醒、状态页「今天完成几个番茄」；
- 钓鱼：商店里的鱼饵货架；图鉴里的「鱼」分区；
- 调试页里对应的分组。

**保留**

- 存档里的所有数据：番茄钟今天的计数、鱼篓里的鱼、图鉴里收集过的鱼；
- 背包里的鱼饵和鱼：照常显示，鱼照样能喂猪、能卖（它们已经是物品了，不算钓鱼玩法本身）。

**核心侧**

- 关闭的扩展：对应动作一律返回「这个扩展已关闭」；番茄钟不再在轮询里结算；
- 图鉴的总进度只算打开的分区（关掉钓鱼，进度不会因为鱼没收集而显得很低）。

## 7. 界面

主菜单新增一个 App「扩展」🧩，放在「设置」前面。进去是一列卡片，每个扩展一张：

```
┌─────────────────────────────────────┐
│ 🍅  番茄钟                    [ 开 ] │
│ 专注 15/25/45 分钟，猪安静陪着你，     │
│ 每天前 8 个有奖励                     │
├─────────────────────────────────────┤
│ 🎣  钓鱼                      [ 开 ] │
│ 抛竿、看准时机提竿……                   │
│ 猪钓鱼回来后才能关                    │  ← 进行中时显示，开关置灰
└─────────────────────────────────────┘
        以后会在这里下载更多扩展
```

- 开关沿用设置页的样式（这次已经做好的 `.dp-switch`）。
- 为什么单独做一个 App 而不是放在设置里：扩展以后会越来越多，每个要有说明、状态，将来还有下载；放设置里会把设置撑得很长。

## 8. 以后加新扩展的步骤（以种菜为例）

1. `data/extensions.js` 加一条（key、名称、emoji、说明、apps、actions……）；
2. 核心写它自己的存档字段和 `ensureXxx`、动作、结算；结算挂到 `freshen` 时先问 `extensionOn`；
3. 路由加动作，名字写进这条扩展的 `actions`（统一拦截）；
4. 客户端加 App 页，主菜单格子会按开关自动出现或隐藏；
5. 测试照第 10 节的清单补一遍。

## 9. 以后的在线下载（这次不做）

真正「下载安装扩展」需要另外解决：扩展包格式、来源校验（签名/哈希）、和游戏版本的兼容声明、卸载与数据清理、DSH 网页版能不能加载外部代码。这些等第一批扩展跑稳、并且有一个真正需要下载的扩展时再单独设计。这次的注册表格式会保证以后能往里加「从哪下载、需要哪个游戏版本」这类字段，不用推翻重来。

## 10. 测试与验收

- 核心：老存档默认全开；开关写进存档；关闭后对应动作被拒、番茄钟不结算；进行中不能关；重新打开数据原样；认不出的 key 保留。
- 客户端：关闭后主菜单格子、图标栏、角标、鱼饵货架、图鉴鱼分区、状态页那一行都消失；正开着的页面退回主菜单；重新打开都回来。
- 网页版（DSH 隔离实例）和桌面版都实际点一遍并截图。

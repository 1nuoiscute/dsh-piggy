# I 批次：桌面版窗口几何重做（根治「更新后偏移 / 拖动异常」）

> 来源：用户 2026-10-06 反馈（v0.32.0 之后）：「经常会碰上更新之后右键桌面版的猪会偏移，拖动异常，上下屏拖动问题……linux 就算了，为什么 windows 下稳定性也这么差？」
> 用户明确要求：**不要再打补丁，换掉底层逻辑**。
> 本卡的根因不是推测：读代码 + 一轮只读审计（含用纯函数复现的模拟数字）。标「待实测」的地方会写明。
> 分工：Claude 写卡 + 实现 + 自测 → 用户实机验收。

---

## 0. 症状与目标

**症状**（用户原话归并）：

1. 更新之后，右键猪（开面板）猪会**偏移**，而且偏了就一直在那儿。
2. 拖动**异常**：不跟手、跳动、和窗口不同步。
3. **上下屏**（垂直叠放的两块显示器）拖动会突然被弹回。
4. Windows 也一样不稳，不只是 Linux。

**目标**（都要能验收，见第 7 节）：

- 开、关面板、切页、冒气泡、换皮肤、更新之后——**猪的屏幕坐标一像素都不动**。
- 拖到哪就是哪：鼠标和猪的相对位置不漂、不弹（跨屏缝也一样）。
- 同一台机器上，**连续开关面板 10 次的位置完全一致**（现在第一次可能是对的，第十次偏了）。
- 更新（游戏包热更新）前后，同一操作的结果一致；版本错配**能被发现并说出来**，而不是悄悄错位。

## 1. 根因（结构性，五条，都有代码证据）

### R1 摆放是「预测一次性发出」，没有任何回读校验 —— 上一版的「量完再修」被删了

2026-10-04 的 `41fd3ca` 把「摆完 → 页面量出猪真实位置 → 主进程再补一次」的反馈回路删掉，改成一次预测到位：
`src/client/desktop/index.js:101-110`（用**缓存**的窗口原点 + **预测**的猪本地框算目标）→ `place.js:66-67` → `main.js:434-447` 照做（2px 死区）。

`anchorCorrection`（`apps/desktop/lib/window-geometry.js:196-225`）**现在只有测试引用，生产代码一次都不调用**（grep 核对）。

**后果**：模型与现实的任何偏差（Windows 取整、缓存过期、夹取、钉边没落准）**不会被修正，而是被下一次计算继承**——这就是「偏了就一直在那儿」。

**为什么当初没测出来**：F10 的验收采的是**渲染端自己算出来的**屏幕坐标（`docs/tasks/F-round.md:177-178`），那正是页面自己的模型，看不见 OS 层面的偏差；而且只在 Linux/Wayland 上测，Windows 明确留了「用户实测」（`F-round.md:149`）。

### R2 页面只有「缓存的窗口原点」这一个真相，它过期就变成真实的猪位移

缓存在 `apps/desktop/preload.cjs:5-42`；同步路径（`place` / `askGeometry`）才刷新，其余靠主进程异步推。

**已核实的漏洞**：面板开着拖完，**不同步几何**——`src/client/desktop/index.js:170` 是 `if (!measure.state.compact) return`，只有收起态才同步。而拖动期间页面故意不 tick（`:124-131`），主进程却以最高 60Hz 挪窗口（`main.js:374-383, 414, 416-422`）。快甩一下就会在缓存里留下几十像素的落差，**下一次内容变化（右键开面板）把它当成真实位移用掉**。

另外 `place.js:62` 的 `resting`（开面板那一刻记下的猪原位）**只算一次，之后不再刷新**（`:75` 只在收起时清）。所以第一次的误差会在面板开着期间的**每一次**内容变化上重复使用。

### R3 持久化状态会被「更新」悄悄作废（这就是「只有更新后才犯」）

- 面板预留范围的 key 里带**实测的猪宽**：`measure.js:158` = `朝向|朝向|Math.round(pigBox.width)`，**key 没有版本、没有迁移**；`validOpenBox`（`:26-34`）的存在本身就说明旧 key 曾经出过事（`603f4bd` 修过一次）。
- 游戏包更新会换掉桌面 CSS / emoji 字体 / 立绘 → 猪的实测宽度可能变 → key 失配 → **收起态不再预留面板** → 那次右键成为「更新后第一次真的改窗口」，R1 的残余就在这一刻显形。
- 更新必然重启 App，而启动是两套位置存储最容易打架的时刻：外壳的 `window.json`（`main.js:141-170, 233-251`）和游戏包的 `localStorage`（`place.js:15, 26-29`）。**现代游戏包下外壳那套是死代码**：`main.js` 的 `lastPigWindow` 只在旧路径 `:354` 赋值 → `window.json` 永远 `pig: undefined`（`:166`）→ 外壳的 `savedPigScreen` 恒为 null。
- 而且 `remember()` 存的是**预测值**（`place.js:91-93` 用 `lastPigWindow`），不是实测值——错的位置会被存下来给下次启动用。

### R4 多屏（尤其上下屏）的夹取逻辑会主动把猪弹走

- 拖动时每帧取「**鼠标所在那块屏**」的工作区（`main.js:377-382`），而 `absoluteDragBounds`（`window-geometry.js:154-173`）要求**整只猪**落在**单块**屏里，禁止跨缝。
  **模拟**（纯函数复现）：上下两块屏（上 y 0–1040、下 y 1080–2120），56px 的猪在下屏 y=1500 开始拖，鼠标移到 y=1070（越过缝 10px）→ 目标 1070 被夹到 984，**10px 的鼠标移动让猪弹了 86px**（另一组参数弹过 516px）。弹回量最多是「猪高 + 任务栏」。
- 散步 / 旧游戏包走 `moveAcrossDisplays`（`:131-141`），夹的是所有屏的**外接矩形**而不是真实并集。**模拟**：上屏 1920 宽、下屏 2560 宽左对齐 → 并集 x 0–2560，允许窗口停在 x=2000，而上屏只到 1920 —— **猪能被走到不属于任何屏幕的地方**。
- `geometry.js:66-76 nearestArea` 按距离挑，平手时按 `getAllDisplays()` 顺序，而这份列表是上次推送时的**快照**，缝附近可能挑错。
- **全项目零处处理 `scaleFactor`/`devicePixelRatio`**（`apps/ src/ test/ scripts/` grep 无命中）；混合 DPI 只靠两个 2px 容忍硬扛。

### R5 版本闸门是摆设，所以「旧外壳 + 新游戏包」既拦不住也看不见

- `apps/desktop/package.json` 的 `piggy.minShell` **从引入起一直是 `0.1.0`**（git log -p 核对，外壳到 0.5.0 都没升），而契约已经到 `DESKTOP_VERSION = 3`（`src/client/desktop/index.js:15`），游戏包的桌面模块实际需要外壳 ≥ 0.3.0。`versions.js:126-127` 只在 `minShell > shellVersion` 时拦——**永远不成立**。
- `loader.js:28` 写进去的 `data-piggy-desktop` **全项目没有任何地方读**（只有 CSS 和一条测试）。
- 而几何逻辑**整个在游戏包里**（可热更新），外壳只负责执行。所以每次「设置 → 更新」之后，你们默认就跑在「新几何 + 旧外壳」的错配状态里，运行时无法察觉。

**另有两条放大器（不改，但要知道）**：透明窗口每次 `setBounds` 都可能闪/叠影（`main.js:191-193, 210-215`，就是 HANDOFF 里那条「抽动 + 一帧叠影」）；窗口 60Hz 移动 vs 页面 30fps 绘制（`main.js:32-33, 261`）。

## 2. 做完之后必须成立的不变量

| | 不变量 | 怎么判定 |
|---|---|---|
| **I1** | 猪的屏幕坐标**只有两个来源**能改：用户拖动（含散步）、用户换体型档/显示器变化时的显式重锚。开合面板、气泡、切页、换皮肤、更新、测量抖动都不许改 | 连续开关面板 10 次，采样猪的屏幕坐标，波动 ≤1px |
| **I2** | 每次摆放 = **读回 → 计算 → 应用 → 验算**；验算超差就修一次（≤2 次 `setBounds`，且只在超差时第二次） | 假 shell 注入 1–2px 的 setBounds 偏差，最终猪的屏幕点仍与目标差 ≤1px |
| **I3** | 磁盘/localStorage 里的位置是**显示器相对坐标 + 布局签名**，带 schema 版本和迁移；显示器变了也能落地 | 旧格式能迁移；拔掉一块屏后猪仍在某块屏上 |
| **I4** | 拖动夹取**允许跨缝**，只在整只猪能被另一块屏装下时才跟随切换 | 上下屏缝上 10px 移动，猪位移 ≤ 鼠标位移 + 4px |
| **I5** | 游戏包启动时**探测外壳能力**，缺能力就明确降级/提示；加基础动作就升 `minShell` | 伪造旧外壳，界面出现「桌面程序版本过旧」提示 |

## 3. 怎么换（设计）

### 3.1 所有权（改完是这样）

| 东西 | 唯一所有者 | 说明 |
|---|---|---|
| 猪的**屏幕坐标** | 游戏包（显式状态，I1） | 只有拖动/重锚改它；存显示器相对坐标 |
| **窗口矩形** | 外壳执行、游戏包计算（现状不变） | 但计算**必须用回读值**（I2） |
| **猪在窗口里的本地框** | 游戏包，按**布局签名**缓存 | 签名 = 面板朝向 + 开合 + 体型档 + 猪宽(4px 量化) + scaleFactor |
| 拖动期间的夹取规则 | 主进程，**按下时定一次** | 不再每帧按鼠标所在屏重算 |

### 3.2 闭环（消灭 R1、R2）

- `placement.decide()` 的 `bounds` 入参改成**决策时同步回读**的窗口矩形（`place({})` / `askGeometry()` 已经是同步 IPC，直接可用），不再用 preload 的缓存做决策输入。
- 新增一次**验算**：`place()` 后用「回读窗口 + 实测 `layoutBox(.dp-pig)`」反算猪的屏幕点，与目标比，>1px 就再 `place()` 一次（有界，最多一次；只在这种超差时才会多一次 `setBounds`，不违反 2px 死区的初衷）。
- `resting` 在面板开着期间**每次内容变化都用回读值刷新**，不再是「算一次用到底」。
- `endDrag` **所有情况**都重新标定几何（补上 `desktop/index.js:170` 那个 early return）。

### 3.3 位置状态（消灭 R3）

- 存 `{ displayId, x, y }`（相对该显示器 `workArea` 左上角）；启动时换算绝对坐标；显示器没了 → 最近的屏 + 夹住。
- 面板预留范围 key 改成 `dsh-piggy:desktop-layout:v2:<签名>`，带 schema 版本；旧 key 一次性忽略并按需重建（不迁移内容，避免把坏数据带过来）。
- `remember()` 存**实测**的猪屏幕点，不再存预测值。

### 3.4 拖动夹取（消灭 R4）

- 按下时确定夹取策略：**允许跨缝**——只要猪的框和**某一块**屏的工作区有交集就合法（多矩形夹取，不是单矩形）。
- 只有「整只猪能被另一块屏装下」时才让夹取区域跟随切换，避免边界抖动。
- `moveAcrossDisplays` 改成按**真实显示器矩形集合**夹取，而不是外接矩形，消除死区。

### 3.5 版本闸门（消灭 R5）

- `minShell` 与 `DESKTOP_VERSION` 绑定：加基础动作就一起升。
- 游戏包启动时**能力探测**（`place`、`logs.save`、`setShape`…）：缺关键能力 → 走保守路径 + 设置页显示「桌面程序版本过旧，请更新」。
- 待实测确认后再删旧路径（见阶段 4）。

## 5. 不做 / 做了也没用（写清楚免得来回试）

- **「窗口开成全屏透明、猪用 CSS 在里面挪」**：最彻底，但你们已经试过并否掉了（`HANDOFF §8.2`「透明全屏窗口拖动会卡整机」）。不回头。
- **Windows 分数缩放下 `setBounds`/`getBounds` 差 1px**：Electron/系统的行为，消不掉。闭环能做到「当次修掉、不累积」，做不到「不发生」——这是天花板。
- **让页面直接设窗口绝对位置**：Electron 只有 `setBounds`，跨 DPI 的换算仍在系统手里。绕不过去。

## 6. 风险与兼容

- **存档不动**：本卡只碰桌面几何，不碰 `state.json`、不升 `STATE_VERSION`。
- **localStorage**：阶段 2 换 key，旧 key 忽略即可（最坏情况是位置回到默认角落一次，不会丢游戏数据）。
- **回退**：阶段 0–3 都可单独 revert（纯游戏包）；阶段 4 涉及删代码 + 外壳升版，回退需要旧外壳，所以放最后、且确认最小支持版本后再做。
- **每个阶段都要先写会失败的测试**（沿用本仓规矩），测试名用中文一句话说清行为。
